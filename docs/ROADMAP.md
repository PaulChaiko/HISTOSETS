# План развития HISTOSETS

Каждое обновление — отдельная ветка, PR с описанием изменений и проверок, Windows-сборка для приёмки. После приёмки изменения объединяются в `main`. Готовность определяется работающими сценариями и сохранностью данных.

План update5 уточнён по документам «Use cases» и «Концепции». Новые требования вводят самостоятельные объекты-изображения, учебные группы аналогов, системные типы тегов, полную локализацию, кисть с ластиком, физические измерения и шесть методов самопроверки. Работа разделена по зависимостям.

| Этап | Результат | Условие готовности |
|---|---|---|
| **update1** | Надёжный запуск, обработка ошибок, сохранение старой разметки, прототип масштабирования | Windows-дистрибутив; исходные материалы и тайловый прототип проверены |
| **update2** | SQLite и импорт XML | Импорт без потери описаний и геометрии; полная резервная копия и восстановление |
| **update3 — после 1.0** | Работа со сверхбольшими изображениями | Реальные сканы, построение пирамид, фоновый импорт, проверка памяти и скорости |
| **update4** | Поиск, языковые варианты, теги и фильтры | Поиск по названиям, назначение тегов и сочетание фильтров, переключение материалов |
| **update5.1** | Основа нового каталога, стартовый экран и режим просмотра | Создание/выбор именованной базы; RU/EN всего интерфейса; типовые теги и аналоги; основной просмотр с масштабом и навигатором; схема 2 и резервная копия перед миграцией |
| **update5.2** | Постоянный редактор карточек, элементов и векторных областей | Все черновики доступны в списке; создание и повторное открытие объекта; несколько изображений; RU/EN-тексты; эллипс/прямоугольник/полигон; Undo/Redo и защита несохранённых правок; схема 3 с JSON геометрией |
| **update5.3** | Кисть, ластик и физические измерения | Составные векторные области с отверстиями и раздельными фрагментами; калибровка изображения по двум осям; площадь и полный периметр каждой области; сохранение в схеме 4 и совместимость со старыми каталогами |
| **update6** | Перенос и объединение каталогов | Экспорт выбранных карточек со связанными данными; проверка пакета; предварительное сравнение и решения по конфликтам; история сравнения в схеме 5; полная копия перед транзакционным импортом |
| **update7.1** | Подготовка самопроверки | Несколько учебных описаний RU/EN для объектов и элементов; выбор материалов, методов и порядка; проверка пригодности и предварительный план занятия; схема 6 и совместимость обмена |
| **update7.2 — текущий этап** | Выполнение пяти методов распознавания | Изображения, выделенные области и учебные описания; ответы из списков с поиском или четыре изображения; учёт аналогов; обратная связь, пропуск и разбор результатов без записи попыток в БД |
| **update7.3** | Самопроверка обведением | Инструменты рисования, сравнение с эталоном, отдельные показатели покрытия и лишнего выделения |
| **1.0** | Стабильная настольная версия | Принятые сценарии, инструкции, сборка и проверенное обновление существующих каталогов |

Поддержка сверхбольших изображений перенесена после релиза до получения реального материала. Масштабирование обычных изображений входит в update5.1 и не зависит от этого этапа.

## Границы update5

**update5.1** подготовил связи и операции, необходимые редактору: статус объекта, основное изображение, метаданные каталога, аналоги, типы тегов и основу хранения калибровки. В этой исторической версии контуры ещё хранятся в таблицах точек; интерфейса калибровки нет.

**update5.2** реализует цикл редактирования: список всех карточек, рабочая копия объекта, завершение/отмена контура, явное сохранение, выход с несохранёнными правками и повторное открытие. Прямоугольник, эллипс и полигон хранятся в `regions.geometry_json` формата 1. Схема 3 содержит 18 таблиц; перед миграцией схем 1/2 создаётся полный архив исходной базы. Статус готовности задаётся после явной проверки; черновик допускает неполные тексты и отсутствие изображения. [Инструкция и приёмка](update5.2.md). Windows CI и пользовательская приёмка оцениваются отдельно по конкретной сборке.

**update5.3** добавляет кисть и ластик с регулируемым радиусом. Сложная область хранится вектором с кольцами, отверстиями и раздельными компонентами; `compound` использует JSON версии 2. Старые фигуры сохраняют JSON версии 1. Калибровка задаётся по известной физической ширине и высоте всего исходного изображения; техническое DPI не заменяет физический масштаб. Площадь и периметр вычисляются по сохранённой геометрии и масштабу каждой оси, без отдельного кэша в БД. Полный периметр включает границы отверстий. [Инструкция, точность и приёмка](update5.3.md).

Кисть с ластиком остаются требованиями редактора. Разделение этапов не заменяет их свободной обводкой.

## Обмен update6

Частичный пакет переносит выбранные карточки целиком, включая все языки, оригиналы изображений, геометрию и калибровку. Необходимые теги, типы тегов и группы аналогов входят в пакет, остальные члены группы аналогов не добавляются автоматически. Исходный XML и история предыдущих обменов не передаются.

Один UUID определяет одну сущность; имена не используются для автоматического объединения. История сравнения отделяет изменения источника от локальных правок. Первый отличающийся вариант без такой истории требует решения, даже если его счётчик редакции больше. Изменения общих справочников рассматриваются отдельно, поскольку они могут затронуть карточки вне пакета. [Порядок работы и приёмка](update6.md).

## Самопроверка update7

Предусмотрены методы:

1. Назвать объект по изображению.
2. Выбрать изображение по названию из четырёх вариантов.
3. Назвать элемент по выделенной области.
4. Обвести области указанного элемента.
5. Определить объект по специальному учебному описанию.
6. Определить элемент по специальному учебному описанию.

Пользователь выбирает объекты по поиску/тегам, методы и порядок предъявления: случайный, сначала метод или сначала объект. Для каждого метода проверяется наличие необходимых данных. Аналоги учитываются как общий допустимый ответ; среди четырёх изображений нельзя незаметно получить несколько правильных вариантов одной группы.

**update7.1** реализовал подготовку занятия. Учебных описаний может быть несколько у карточки и каждого элемента. Они хранятся отдельно от обычных кратких и полных описаний; варианты можно отключать и переводить независимо. Пригодность рассчитывается для конкретного метода и выбранного языка, а не только по общему статусу draft/ready. Для вариантов ответа используются данные всего каталога; выбранные карточки определяют цели вопросов. [Инструкция и приёмка](update7.1.md).

**update7.2** выполняет пять методов распознавания по подготовленному плану. Ответ фиксируется однократно; затем показывается правильный вариант. Есть пропуск, досрочное завершение и разбор каждого задания. Верные и неверные ответы, пропуски, недоступные задания и оставшиеся без ответа учитываются отдельно. Доля верных рассчитывается только среди данных ответов; числовая оценка и порог прохождения не назначаются. Язык, очередь и учебные данные фиксируются на время занятия; изображения проверяются перед показом. Каталог остаётся неизменным, схема — 6. [Инструкция и приёмка](update7.2.md).

Обведение в смешанном плане отложено до **update7.3** и не входит в итоги занятия update7.2. План только из заданий на обведение нельзя запустить.

По исходным Use Cases ответы на распознавание выбираются из выпадающего списка с поиском. Свободный ввод с автоматической оценкой формулировок не требуется.

Оценка обведения должна отдельно отражать покрытие эталона и лишнее выделение. Итоговую шкалу и пороги надо согласовать. История попыток не включается без отдельного требования.

## Общие архитектурные правила

- Настольная SQLite и будущая PostgreSQL используют одну логическую модель; физические типы и миграции адаптируются под СУБД.
- Объект каталога — самостоятельная карточка с основным изображением. Связь `material_images` сохраняет дополнительные изображения и повторное использование одного файла.
- Учебная группа аналогов объединяет объекты с общим допустимым названием. Она не является учётом физического препарата. Объект входит максимум в одну такую группу.
- Элемент может иметь несколько областей. Переводы не создают копий геометрии. Координаты относятся к исходному изображению, независимо от масштаба окна.
- Изображения хранятся управляемыми файлами; БД содержит ключ, размеры, формат, контрольную сумму и связи. Изменение оригинала требует явного решения о разметке и калибровке.
- Типы тегов задаются системой; значения создаются пользователем и переиспользуются. Старые пользовательские группы сохраняются до явного сопоставления.
- Для обмена сохраняются UUID, происхождение, редакции и отметки удаления. Совпадение названий не означает совпадение объектов.
- Просмотр, редактирование и самопроверка используют общие данные и правила геометрии. Черновик можно сохранить; готовность проверяется явно.

Веб-версия и отдельный учёт физических препаратов остаются за пределами текущих этапов. Термин «объект» не ограничивает каталог только гистологическими изображениями: модель допускает другие учебные изображения после согласования их требований.
