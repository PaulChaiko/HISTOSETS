# План развития HISTOSETS

Каждое обновление — отдельная ветка, PR с описанием изменений и проверок, сборка для владельца проекта. После приёмки изменения объединяются в `main`. Обновление считается завершённым по работающим сценариям и сохранности материалов.

| Этап | Результат | Условие готовности |
|---|---|---|
| **update1** | Надёжный запуск, обработка ошибок, сохранение старой разметки, прототип масштабирования | Собираемый Windows-дистрибутив; проверены исходные материалы и тайловый просмотр |
| **update2** | SQLite и импорт XML | Все материалы импортируются без потери описаний и геометрии; резервная копия и повторяемые миграции |
| **update3** | Просмотр больших изображений | Построение пирамид, фоновый импорт, отзывчивый интерфейс и проверка на реальных больших препаратах |
| **update4** | Каталог, поиск и теги | Отдельный поиск по названию, фильтрация по тегам и их группам, удобное переключение материалов |
| **update5** | Постоянный редактор | Создание материала/элемента, несколько областей на элемент, сохранение и отмена, защита от потери несохранённых правок |
| **update6** | Перенос и объединение каталогов | Пакет экспорта, UUID, версии, контроль изображений, обнаружение конфликтов, резервное восстановление |
| **update7** | Самопроверка | Задания по известным элементам и областям, скрытые подписи, оценка и разбор ошибок |
| **1.0** | Стабильная настольная версия | Принятые сценарии, инструкции, сборка и проверенное обновление существующих каталогов |

## Основа для будущей веб-версии

- SQLite в настольной версии и PostgreSQL в веб-версии используют одну **логическую модель**: материалы, изображения, элементы, области, переводы, теги, авторство и версии. Физические типы и миграции адаптируются под СУБД.
- Изображения хранятся управляемыми файлами; БД содержит идентификатор, путь/ключ хранилища, размеры, тип, контрольную сумму и связь с материалом. Пирамиды и миниатюры производятся из оригинала.
- Материал может иметь несколько изображений. Элемент может иметь несколько областей на разных изображениях. Переводы подписей не дублируют геометрию.
- Координаты новых областей задаются в пикселях ориентированного оригинала. Замена/поворот оригинала требует явного решения о преобразовании разметки.
- Импорт старого XML отдельно учитывает DPI и сохраняет происхождение записи. Существующие русская и английская записи связываются после проверяемого сопоставления.
- Для обмена заранее предусматриваются UUID, версия формата и записи, происхождение, отметки удаления и обнаружение конфликтов. Совпадения названий не используются как идентификаторы.
- Теги отделяются от материала и могут иметь группу: тема, назначение (образовательное/исследовательское), авторские подборки. Конкретный словарь согласуется при работе над каталогом.
- Три режима интерфейса: просмотр, редактирование, самопроверка. Просмотрщик и геометрия общие; самопроверка использует данные редактора.

Веб-версия разрабатывается после стабилизации модели данных. Поддержка анатомических изображений, рентгенограмм и схем закладывается нейтральной сущностью «материал», без привязки всей модели исключительно к гистологическому препарату.
