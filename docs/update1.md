# Update1: запуск, каталог и прототип просмотра

## Граница обновления

Цель — получить воспроизводимо собираемую настольную версию, сохранить исходный учебный материал и проверить технологию масштабирования/разметки до перехода к базе данных. SQLite, постоянный редактор, поиск, теги и самопроверка относятся к следующим обновлениям.

Исходная точка: `3722be1b2a62c445070271d68d45e33be64950f3`. Научные описания, XML и изображения в update1 не редактируются. Рабочая ветка: `update1`; принятие в `main` — после проверки владельцем проекта.

## Исправления основы

В исходном `App.xaml` не была задана точка запуска окна. Теперь окно явно создаётся в `App.OnStartup`. Пространства имён согласованы; необработанная ошибка записывается в журнал и завершает программу с сообщением, вместо продолжения работы в неизвестном состоянии.

Чтение XML вынесено в `HistOSets.Core`. Каталог привязан к папке приложения, а не к текущей рабочей директории. Полностью разобранный каталог хранится в памяти. Выбор записи выполняется по объекту, а не поиском XML-узла по отображаемому имени; одинаковые имена не объединяют записи.

Повреждённый XML даёт сообщение с возможностью повторного чтения. Неверный контур пропускается с замечанием; остальные элементы доступны. Отсутствующее изображение не удаляет запись и не закрывает приложение. XML с внешними сущностями не читается, а `IMAGE` разрешает только пути внутри `SPECIMENS`.

Пустые описания обозначаются в интерфейсе; кнопка подробного описания доступна, только если текст существует. При смене препарата контуры и сведения предыдущего выбора очищаются.

## Координаты и DPI

Старые полигоны заданы в логических единицах WPF (1/96 дюйма). У изображения роговицы большого увеличения размер **2592 × 1944 пикселя**, но DPI **2400 × 2400**. Поэтому диапазон старой разметки около 103 × 77 соответствует изображению, а не свидетельствует о потере масштаба.

Для показа в пиксельной системе:

```text
x_pixels = x_legacy × DPI_X / 96
y_pixels = y_legacy × DPI_Y / 96
```

При недопустимом/нулевом DPI используется 96. Это правило одинаково для основного окна и передачи контуров в новый просмотрщик. Необходимо сохранить эту информацию и при будущем импорте XML в SQLite. Нельзя повторно масштабировать уже преобразованные контуры.

Старые записи без `COORDINATES` считаются `legacy-dip`. Загрузчик также понимает явное `COORDINATES="pixels"` для подготовленных вручную новых записей. Неизвестное значение отклоняется с сообщением. Исходный XML не переписывается.

У роговицы малого увеличения есть вершина x=1969 при ширине 1968 пикселей. Она сохраняется и обрезается границей изображения при отображении. Исправлять контур без предметной проверки не следует.

Основное окно декодирует превью с максимальной стороной 4096, при этом размеры холста и координаты остаются в пикселях оригинала. После загрузки файл изображения освобождается.

## Новый просмотрщик

WPF открывает WebView2 с локальным пакетом OpenSeadragon 6.1.1 + Annotorious 3.9.3. Нет внешних CDN, веб-сервера или подключения к БД. Виртуальные HTTPS-адреса сопоставляются с локальными папками. Внешняя навигация и всплывающие окна отключены; из JS в приложение передаются только сообщения о готовности, загрузке и ошибках.

Опубликованный пакет Annotorious содержит собственную сборку Pixi 7. Ей требуется `unsafe-eval` для построения шейдеров; отдельный модуль `@pixi/unsafe-eval` не подменяет встроенную копию. В прототипе это разрешение ограничено локальной страницей с собственными скриптами. Перед переносом в публичную веб-версию нужно отдельно выбрать сборку/версию и политику CSP; текущую политику нельзя автоматически считать итоговой для веб-сервиса.

Граница обмена: название, источник изображения, список элементов и набор пиксельных полигонов для каждого элемента. Этот прототип не определяет будущую схему БД: элементы с несколькими областями уже поддержаны, идентификаторы в прототипе действуют только на время просмотра. Постоянные UUID и версии добавляются при проектировании SQLite/PostgreSQL.

Прямоугольники и полигоны можно нарисовать для проверки взаимодействия. Данные остаются в памяти окна; кнопка восстановления возвращает исходные контуры. Это явно обозначено в интерфейсе.

Кнопка DZI открывает уже построенную пирамиду. Подготовка пирамид, фоновые операции, кэширование и испытания на настоящих больших сканах входят в update3. Синтетическая проверка 201 Мп подтверждает смену уровней и выборочную загрузку тайлов, но не даёт оценки всех форматов сканеров и предельного потребления памяти.

## Приёмка владельцем

1. Распаковать сборку целиком и запустить `HistOSets.exe`.
2. Открыть роговицу обоих увеличений, кожу, мочевой пузырь и трахею; сравнить контуры с привычной версией.
3. В новом просмотрщике проверить приближение, перемещение, выбор элемента и заливку.
4. Нарисовать пробную область и восстановить исходные контуры.
5. Проверить читаемость интерфейса при используемом масштабе экрана Windows.

После приёмки можно объединить PR в `main` и начать update2. Самопроверка не меняет это решение и остаётся последним функциональным этапом.
