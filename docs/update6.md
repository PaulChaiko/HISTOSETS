# update6 — перенос и объединение каталогов

Обновление добавляет обмен выбранными карточками через файл `.histosets-exchange`. В пакет входят оригиналы изображений, все переводы, элементы, области, калибровки, назначения тегов и необходимые записи справочников. После импорта карточку можно сразу открыть в редакторе; просмотр доступен при наличии изображения.

## Экспорт

1. Откройте исходную базу и выберите **«Обмен материалами…»** на стартовом экране.
2. На вкладке экспорта отметьте нужные карточки. При необходимости включите показ удалённых объектов и выберите отметки удаления явно.
3. Сохраните пакет в новый файл `.histosets-exchange`.

Карточка переносится целиком, включая дополнительные изображения и языки, которые сейчас не отображаются в интерфейсе. При наличии общей группы аналогов в пакет включается сама группа, но не остальные её карточки. Один оригинал, используемый несколькими выбранными карточками, записывается один раз. Шесть системных типов тегов включаются всегда; остальные справочники — по связям выбранных карточек.

Исходный XML не включается: он может содержать другие, не выбранные объекты. Ссылки на локальный журнал XML-импорта не переносятся в другую базу. UUID и происхождение самих объектов сохраняются. Для полной копии каталога, включая XML и служебную историю, используйте прежнюю команду резервного копирования.

## Импорт

1. Откройте целевую базу и окно обмена.
2. Выберите пакет на вкладке импорта. Сначала выполняется проверка архива; база ещё не изменяется.
3. Просмотрите предлагаемые действия, локальные и входящие сведения. Теги, их типы и группы аналогов рассматриваются отдельно, поскольку они могут использоваться другими карточками.
4. Разрешите конфликты и подтвердите необходимые удаления. Для каждого спорного объекта можно сохранить локальный вариант, принять входящий или пропустить его.
5. Примените выбранные решения. Перед изменением создаётся полный архив, затем выполняется транзакционный импорт.

| Результат сравнения | Предлагаемое действие |
|---|---|
| UUID отсутствует в целевой базе | Добавить объект. |
| Содержимое совпадает | Оставить без изменений. |
| После прошлого обмена изменился только источник | Предложить обновление. |
| Изменилась только локальная запись | Сохранить локальное содержимое. |
| Разные изменения с обеих сторон | Потребовать решение. |
| UUID совпадает, содержимое отличается, истории сравнения ещё нет | Потребовать решение независимо от номера редакции. |
| Входящий вариант содержит удаление | Потребовать явное решение. |

**Совпадение названий не объединяет разные UUID.** Более высокая ревизия сама по себе не означает, что входящая копия новее всех локальных правок. Отличающийся пакет с ревизией не выше последней принятой также требует решения, чтобы старый файл не откатил более свежие данные автоматически. Принимается целая карточка или целая запись справочника; автоматического слияния отдельных текстовых фрагментов и контуров нет.

Карточка, которой нет в частичном пакете, остаётся в целевой базе. При принятии входящей версии существующей карточки её состав заменяется выбранной версией; исчезнувшие дочерние записи получают отметки удаления. Общие файлы изображений автоматически не удаляются. Если изменение справочника лишило готовую карточку обязательных сведений, она становится черновиком и требует повторной проверки готовности.

После изменения базы предварительный план устаревает: пакет нужно проверить заново. Это защищает от применения решения, принятого до более свежего сохранения. Отмена окна предварительного просмотра ничего не записывает в базу. Повторный импорт уже принятого, неизменённого содержимого не создаёт дубликатов. Если различий вообще нет, не создаются также резервная копия и новая запись истории обмена; последующее первое расхождение без истории потребует ручного решения. Сохранение отличающейся локальной версии и пропуск не делают отвергнутый вариант новой общей основой сравнения.

## Хранение и совместимость

Приложение имеет версию **0.6.0**, схема SQLite — **5**, таблиц — **19**. Новая `exchange_baselines` хранит UUID источника, вид и UUID сущности, отпечатки входящего и принятого локального содержимого, ревизию источника и время решения. Геометрия по-прежнему находится в `regions.geometry_json`: версия 1 для примитивов, версия 2 для составных областей. Внешний JSON-файл на каждую карточку не создаётся.

При первом открытии базы схемы 1–4 создаётся полный архив:

```text
<папка каталога>/BACKUPS/before-schema5-<UTC>-<UUID>.histosets
```

Затем необходимые миграции выполняются одной транзакцией. Перед применением изменений пакета создаётся отдельная копия `BACKUPS/before-exchange-…histosets`. Если копию создать невозможно, импорт не начинается. Для возврата к предыдущей версии приложения восстановите совместимую с ней копию до миграции в отдельную пустую папку.

Пакет обмена и резервная копия имеют разные назначения:

| Формат | Содержимое и назначение |
|---|---|
| `.histosets-exchange`, версия 1 | Выбранные объекты; проверка и объединение с существующей базой. |
| `.histosets`, версия 1 | Весь каталог с SQLite, исходными XML и изображениями; восстановление в пустую папку. |

Проверяются относительные пути, отсутствие повторов и лишних файлов, размеры и SHA-256, версия формата, допустимые поля, UUID, внешние ключи, геометрия и согласованность калибровки. Интерфейс также декодирует изображения и сверяет фактические размеры с пакетом. SQL из пакета не исполняется. SHA-256 проверяет целостность, но не подтверждает личность автора пакета. Предельные размеры: 100 000 выбранных объектов, 100 000 изображений, 64 ГиБ графа и изображений вместе, 128 МиБ графа данных, 500 000 строк и 16 МиБ манифеста. Испытания реальных сверхбольших сканов остаются после 1.0.

## Приёмка

Проверяйте сборку из успешного запуска [GitHub Actions](https://github.com/PaulChaiko/HISTOSETS/actions/workflows/windows.yml) для нужного коммита `update6`. Артефакт — **HISTOSETS-update6-windows-x64**.

1. Экспортировать одну из нескольких карточек с составной областью и калибровкой. Убедиться, что невыбранная карточка не предлагается при импорте.
2. Импортировать пакет в пустую базу. Открыть карточку, проверить тексты RU/EN, изображения, теги, аналог, геометрию и измерения.
3. Повторить импорт: нет дубликатов и изменений содержимого.
4. После первого обмена изменить текст только в источнике: предлагается обновление. Изменить обе копии по-разному: появляется конфликт.
5. По очереди проверить сохранение локальной и принятие входящей версии. Проверить, что неразрешённый конфликт блокирует применение.
6. Передать явно выбранную отметку удаления; убедиться, что другие объекты остаются на месте.
7. Отменить предварительный просмотр и попробовать повреждённый пакет: база не меняется.
8. Проверить наличие полной копии до импорта и возможность восстановить её в другую пустую папку.

Автоматические проверки охватывают хранение и настоящие окна Windows; результат CI относится к конкретному коммиту и не заменяет пользовательскую приёмку. Следующий этап — самопроверка `update7` по согласованным сценариям.
