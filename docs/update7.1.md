# update7.1 — подготовка самопроверки

Этот этап позволяет подготовить материалы, выбрать состав занятия и получить проверенный план заданий. Выполнение заданий, ответы и результаты появятся в update7.2; обведение и сравнение с эталоном — в update7.3. История попыток пока не сохраняется.

## Учебные описания в редакторе

1. Откройте карточку через **«Редактирование»**.
2. Для описания объекта откройте его учебные описания. Для описания элемента сначала выберите нужный элемент, затем откройте его учебные описания.
3. Добавьте один или несколько вариантов. У каждого варианта собственные тексты RU/EN, порядок и флаг использования в самопроверке.
4. Примените изменения окна описаний, затем сохраните карточку. До сохранения карточки база не меняется.

Обычные краткое и полное описания остаются отдельными полями. Они не копируются автоматически в учебные тексты, поскольку часто содержат ответ. Варианты можно менять местами, временно отключать и удалять. Отмена окна оставляет исходную рабочую копию; применённые изменения поддерживают Undo/Redo редактора. При редактировании RU/EN переводы на других языках сохраняются.

Формулируйте описание по признакам, без названия объекта, элемента или группы аналогов. Разные варианты помогают сформировать несколько заданий. Для включения варианта достаточно текста на языке выбранного занятия; отсутствие другого перевода не препятствует его сохранению. Учебные описания необязательны для общего статуса готовности карточки.

## Настройка занятия

1. Выберите базу и нажмите **«Самопроверка»** на стартовом экране.
2. Найдите объекты по названиям и тегам. Выберите один объект, несколько отдельных карточек или всю показанную группу. Выбор, скрытый фильтром, учитывается в счётчике; его можно явно снять.
3. Отметьте методы и выберите порядок: случайный, сначала по методам или сначала по объектам.
4. Сформируйте план. Просмотрите количество заданий, последовательность и причины исключения неподходящих материалов.

Теги одного типа объединяются условием «ИЛИ», разных типов — «И», как в просмотре. В списке доступны и черновики без изображения. Пригодность определяется данными конкретного задания, а не одним общим статусом карточки.

Выбранные карточки определяют **цели вопросов**. Названия для ответов и изображения для отвлекающих вариантов берутся из всего текущего каталога. Поэтому один выбранный объект может участвовать в вопросе с четырьмя изображениями, если в базе достаточно подходящих вариантов.

| Метод | Необходимые данные |
|---|---|
| Назвать объект по изображению | Название на выбранном языке и доступное изображение. Для аналога требуется название его группы на этом языке. |
| Выбрать изображение | Дополнительно нужны четыре различимых варианта с разными ответами и оригиналами изображений. Два аналога одной группы не предлагаются как разные ответы. |
| Назвать элемент по области | Название элемента и видимые области на доступном изображении. |
| Обвести элемент | Название элемента и ненулевой эталон, находящийся в пределах изображения. Физическая калибровка не обязательна. |
| Определить объект по описанию | Включённый учебный вариант и однозначное название объекта/группы на языке занятия. Изображение не обязательно. |
| Определить элемент по описанию | Включённый учебный вариант и название элемента на языке занятия. Изображение и контуры не обязательны. |

Для вопросов по изображению объекта используется одно подходящее изображение, с предпочтением основного. Для элементов отдельное задание формируется на каждое изображение с подходящей группой областей. Области одного элемента на одном изображении рассматриваются вместе. Каждый пригодный вариант учебного описания даёт отдельное задание; повторяющиеся варианты одного владельца не размножают вопросы.

Проверка объясняет отсутствие имени или перевода, недоступный/изменённый оригинал, отсутствие подходящих областей, нехватку вариантов выбора, отключённые и пустые описания, явное включение ответа в описание и неоднозначные совпадения текстов. Одинаковое описание с разными правильными ответами исключается; одинаковые описания внутри одной группы аналогов допустимы. Совпадающие названия разных независимых объектов требуют уточнения названий или корректного назначения аналогов.

Автоматическая проверка текстов находит буквальные совпадения после нормализации регистра, пробелов и пунктуации. Она не оценивает научную точность, грамматические формы и смысловые подсказки: качество учебных формулировок проверяет автор.

## Актуальность и сохранность данных

Открытие подготовки, поиск, фильтры и построение плана не записывают данные в каталог. При изменении состава занятия прежний план сбрасывается. Перед построением снова проверяется содержимое базы и оригиналы изображений. Если исходные данные изменились, список обновляется и требуется повторное формирование плана.

План живёт только в окне подготовки. Он не является сохранённой попыткой, не содержит пользовательских ответов и не выставляет оценку. Исходные контуры и изображения во время подготовки не изменяются.

## База данных и обмен

Версия приложения — **0.7.1**, схема SQLite — **6**, таблиц — **21**. Добавлены `training_prompts` и `training_prompt_translations`. Владелец варианта — карточка или её конкретный элемент; у каждого варианта и перевода собственный UUID. Тексты хранятся внутри SQLite.

Перед обновлением схем 1–5 создаётся полный архив `BACKUPS/before-schema6-…histosets`. Все необходимые миграции выполняются одной транзакцией; геометрия, изображения, калибровки, прежние тексты и история обмена сохраняются.

Новый пакет `.histosets-exchange` имеет **формат 2** и переносит учебные описания вместе с карточкой. Формат 1 из update6 по-прежнему принимается: его отсутствие учебных полей не стирает описания сохранившихся владельцев. При удалении карточки или элемента удаляются также его варианты. Переход к полному пакету после сохранения отличающихся локальных данных может потребовать явного разрешения конфликта. Предыдущая сборка update6 не читает новый формат 2 и схему 6; для возврата используйте копию до миграции.

## Приёмка

Используйте артефакт **HISTOSETS-update7.1-windows-x64** из успешного запуска [GitHub Actions](https://github.com/PaulChaiko/HISTOSETS/actions/workflows/windows.yml) для нужного коммита.

1. Добавить несколько учебных вариантов объекту и элементу, поменять их порядок, отключить один. Проверить отмену, Undo/Redo, сохранение и повторное открытие.
2. Выбрать одну карточку и несколько методов. Убедиться, что план содержит только пригодные задания и объясняет исключения.
3. Переключить RU/EN: отсутствие перевода должно исключить соответствующее задание, а не подставить другой язык.
4. Проверить четыре варианта изображений: разные ответы, без двух представителей одной группы аналогов и без одинаковых оригиналов.
5. Проверить описание без изображения, отключённый вариант, текст с названием-ответом и одинаковое описание у разных ответов.
6. Изменить набор выбранных карточек или язык после построения: прежний план должен быть сброшен.
7. Экспортировать и импортировать карточку с учебными вариантами; проверить тексты, владельцев, порядок и включённость после переноса.

Автоматические проверки и скриншоты Windows относятся к конкретному коммиту. Пользовательская приёмка остаётся отдельным шагом перед слиянием.
