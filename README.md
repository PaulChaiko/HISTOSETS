# HISTOSETS

Настольный атлас изображений с описаниями, разметкой и самопроверкой. В **update8 (0.8.0)** каталог хранится в одном файле `.histosets`. Просмотр, редактирование и самопроверка открывают его напрямую. Этот же формат используется для резервных копий и передачи выбранных карточек.

## Первое открытие

1. Скачайте **HISTOSETS-update8-windows-x64** из успешного запуска [GitHub Actions](https://github.com/PaulChaiko/HISTOSETS/actions/workflows/windows.yml). Войдите в GitHub, если скачивание требует авторизации.
2. Распакуйте архив **программы** целиком и запустите `HistOSets.exe`. Файл **каталога** `.histosets` распаковывать не нужно. Среда .NET включена в переносимую сборку.
3. Выберите **«Открыть каталог .histosets…»** для существующего файла или **«Создать каталог…»** для пустой базы. Чтобы попробовать программу на готовых данных, выберите **«Создать копию демонстрационного каталога…»** на стартовом экране без открытого каталога.

В демонстрационном каталоге 5 объектов, 5 изображений, 10 переводов карточек, 27 элементов и 33 области. Рабочую копию демо можно редактировать независимо от поставляемого образца.

В файле хранятся исходные байты изображений, тексты, контуры, калибровка и справочники. **У карточки только одно изображение.** Теги и группы аналогов редактируются в режиме редактирования. В просмотре фильтры по тегам открываются из верхней панели, а миникарта скрывается переключателем под изображением.

В самопроверке по-прежнему доступны шесть методов. При распознавании поиск помогает найти название, но ответом считается выбранный термин. При обведении «Верно» означает, что и покрытие эталона, и точность выделения составляют не менее 75% каждое. Изменение вида контуров не меняет оценку или исходную разметку.

## Переход с update7.3 и более ранних версий

- В **«Управлении каталогами…» → «Перенести старый каталог…»** выберите файл `catalog.sqlite` из прежней папки с изображениями либо полный резервный архив `.histosets` старого формата. Укажите имя нового файла `.histosets` в свободном месте. Исходник остаётся на месте; после успешной проверки открывайте новый файл.
- Если у прежней карточки было несколько изображений, они становятся отдельными связанными карточками. Сохраняются оригиналы, области, калибровка и учебные описания. Основная карточка сохраняет прежний UUID; следующие получают суффиксы ` · 2`, ` · 3` и т. д.
- Для материалов, которые остались только в XML, сначала выполните импорт в **HISTOSETS 0.7.3**. Аналогично, прежний `.histosets-exchange` нужно сначала объединить с базой в 0.7.3 и затем перенести полученный каталог. В update8 готовый атлас не зависит от исходного XML.
- Если нужно вернуться на старую версию, откройте оставшийся прежний каталог в совместимой сборке. Изменения в новом файле в старый каталог автоматически не переносятся.

## Копирование и передача

| Задача | Действие |
|---|---|
| Передать весь атлас или сделать резервную копию | В управлении каталогами выберите **«Сохранить копию…»**. Копия `.histosets` содержит весь каталог и открывается напрямую на другом компьютере. |
| Передать несколько карточек | В **«Обмен материалами…»** выберите карточки и сохраните новый `.histosets`. Он открывается как самостоятельный каталог. |
| Присоединить материалы к своему атласу | Откройте целевой каталог, в обмене выберите входящий `.histosets`, проверьте предпросмотр и разрешите конфликты перед применением. |

Для передачи открытого каталога используйте команду копирования в программе. После штатного закрытия можно переслать сам файл. Служебные журналы SQLite, которые могут появляться во время записи, для передачи не нужны. Перед изменяющим каталог объединением программа сохраняет отдельную резервную копию, путь к ней показан в результате операции. Обычная копия файла не объединяет изменения, сделанные двумя авторами: для этого служит обмен материалами.

Текущий путь виден на стартовом экране и запоминается в `%LOCALAPPDATA%/HISTOSETS/catalog-path.txt`. Там же, отдельно от каталога, находятся настройка языка и журналы ошибок (`language.txt`, `Logs`).

## Сборка и проверки

Настольная версия требует **Windows и .NET SDK 10**; `global.json` указывает минимальный SDK `10.0.100`. Сначала подготовьте демонстрационный файл, если его ещё нет, затем соберите и запустите приложение:

```powershell
dotnet run --project tools/HistOSets.Demo -c Release -- . Demo.histosets
dotnet build HistOSets.sln -c Release --warnaserror
dotnet run --project HistOSets.csproj -c Release
```

Переносимая сборка:

```powershell
dotnet publish HistOSets.csproj -c Release -r win-x64 --self-contained true -o artifacts/HISTOSETS-update8-windows-x64
```

Проверки ядра и хранения работают на Windows и Linux. Проверка настоящих окон WPF запускается на Windows:

```powershell
dotnet run --project tests/HistOSets.Core.Tests -c Release -- .
dotnet run --project tests/HistOSets.Storage.Tests -c Release -- .
dotnet run --project tests/HistOSets.Windows.Smoke -c Release -- artifacts
```

При проверках пользовательские настройки можно изолировать через `HISTOSETS_SETTINGS_DIRECTORY`. Экспериментальный браузерный просмотрщик в `Viewer/` ведётся отдельно и не нужен для настольной сборки. Испытания реальных сверхбольших сканов отложены после 1.0.
