# HISTOSETS

Настольный атлас изображений с описаниями и разметкой анатомических и гистологических элементов. Исходная версия зафиксирована коммитом [`3722be1`](https://github.com/PaulChaiko/HISTOSETS/commit/3722be1b2a62c445070271d68d45e33be64950f3). Ветка `update4` добавляет поиск, переключение языка, группы тегов и фильтрацию к принятому каталогу SQLite. Фирменное оформление и разметка сохраняются.

## Запуск готовой сборки

1. Откройте [GitHub Actions](https://github.com/PaulChaiko/HISTOSETS/actions/workflows/windows.yml) и последнюю успешную проверку ветки `update4`.
2. Скачайте артефакт **HISTOSETS-update4-windows-x64**. Для скачивания артефактов GitHub требуется вход в аккаунт.
3. Распакуйте весь архив в доступную для чтения папку и запустите `HistOSets.exe`.

Сборка предназначена для Windows x64 с поддержкой .NET 10. Среда .NET включена в архив. При первом запуске комплектные `ATLAS` и `SPECIMENS` импортируются в `%LOCALAPPDATA%/HISTOSETS/Catalog`. После этого данные читаются из SQLite, а копии изображений — из каталога. Обновление распакованной сборки не заменяет каталог. Папка `Viewer` должна оставаться рядом с программой. Запуск через ярлык из другой рабочей папки поддерживается.

Для отдельного окна **«Новый просмотрщик»** нужен установленный [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/#download-section). После установки просмотр работает с локальными файлами без доступа к интернету. Основное окно атласа работает и без WebView2.

## Что входит в update4

- Одна карточка на материал: исходные 5 материалов с переключением RU/EN; все переводы и контуры сохранены. Материал без выбранного перевода показывается на доступном языке с пояснением.
- Поиск по названиям на всех языках: без учёта регистра и е/ё, несколько слов, исходный порядок или сортировка по названию.
- Справочник групп и тегов с русскими и английскими названиями: создание, переименование, смена группы и удаление. Первоначально словарь пуст.
- Назначение тегов материалу и фильтры: любой выбранный тег внутри группы, совпадение всех выбранных групп.
- Фоновая загрузка выбранного изображения с защитой от устаревшего результата при быстром переключении.
- Работа с существующей схемой SQLite 1 без повторного импорта. Резервные копии сохраняют теги, переводы и назначения.

[Инструкция и приёмка update4](docs/update4.md). Тяжёлые пирамиды update3 отложены после 1.0 до появления реальных сканов. Постоянный редактор разметки — update5.

## Основа update2

- SQLite: материалы, несколько изображений на материал, элементы, полигоны, переводы, теги и происхождение. [Описание схемы и совместимости с PostgreSQL](docs/data-model.md).
- Однократный строгий импорт XML: ошибка или недостающий файл отменяют импорт. Повтор того же набора не создаёт дубликатов. Другой XML можно импортировать в отдельный каталог.
- Исходные изображения копируются без изменения байтов и учитываются по SHA-256; абсолютные пути в базе не сохраняются.
- Русские и английские записи принятого набора связаны проверенной картой переводов: 5 материалов, 5 изображений, 10 языковых записей, 27 элементов и 33 общих контура. В просмотре остаются прежние 54 подписи элементов и 66 отображений контуров.
- Окно **«Данные атласа»**: полная резервная копия `.histosets`, восстановление в пустую папку, открытие и создание каталогов. Выбранный каталог запоминается.
- Версия схемы, транзакционный импорт, проверка целостности и защита от одновременного открытия каталога двумя экземплярами приложения.

[Пошаговая проверка update2 и восстановление](docs/update2.md).

## Сохранённые возможности update1

- Исправленный запуск WPF, единое пространство имён `HistOSets`, переход на .NET 10 LTS.
- Сохранено фирменное оформление: фон `LOGO/GBL.png`, центральный логотип `LOGO/LOGO2.png` до выбора препарата, сиреневый список препаратов и розовый список элементов. Новый просмотрщик использует эти же изображения и палитру.
- Каталог загружается один раз; выбор препарата и элемента выполняется одним щелчком.
- Понятные сообщения при ошибках XML, отсутствии изображения или незаполненном описании. Кнопка **«Обновить каталог»** перечитывает SQLite. Для другого XML используется **«Данные атласа → Создать из XML…»**.
- Контуры старого XML переводятся из единиц WPF в пиксели с учётом DPI исходного изображения. XML и исходные изображения сохранены без изменений.
- Новый просмотрщик: приближение, перемещение, обзорная миниатюра, подсветка элементов, настройка заливки и показ/скрытие контуров.
- Пробное рисование прямоугольников и полигонов. **Изменения в этом окне не сохраняются**; это проверка технологии для будущего редактора.
- Открытие готовых локальных пирамид DZI. Рядом с `name.dzi` должна находиться папка `name_files`. Создание пирамид и импорт больших изображений появятся позднее.
- Автоматические проверки каталога, браузерного просмотрщика, запуска WPF и переносимой Windows-сборки.

Исходный набор: 10 записей на русском и английском языках, 5 используемых изображений, 54 языковые записи элементов и 66 языковых отображений полигонов. Пустые описания и отсутствующие контуры не дополняются автоматически.

## Сборка из исходников

Нужны Windows, .NET SDK 10 и Node.js 24 LTS. Версии JS-зависимостей зафиксированы в `Viewer/package-lock.json`; скачивание зависимостей нужно только для сборки.

```powershell
npm ci --prefix Viewer
npm run build --prefix Viewer
dotnet build HistOSets.sln -c Release --warnaserror
dotnet run --project HistOSets.csproj -c Release
```

Получение переносимой сборки:

```powershell
dotnet publish HistOSets.csproj -c Release -r win-x64 --self-contained true -o artifacts/HISTOSETS-update4-windows-x64
```

## Проверки

Проверки данных запускаются на Windows и Linux:

```powershell
dotnet run --project tests/HistOSets.Core.Tests -c Release -- .
dotnet run --project tests/HistOSets.Storage.Tests -c Release -- .
```

Проверки просмотрщика требуют Python 3.12 и Chromium для Playwright:

```powershell
python -m pip install Pillow==12.1.1
python Viewer/tests/make-fixtures.py
npm exec --prefix Viewer -- playwright install chromium
npm test --prefix Viewer
```

На Windows дополнительно проверяются настоящее окно WPF, все препараты и контуры, отсутствие блокировки файла изображения и связка WPF → WebView2 → локальные изображения:

```powershell
dotnet run --project tests/HistOSets.Windows.Smoke -c Release -- artifacts
```

Синтетическая пирамида 16 384 × 12 288 проверяет загрузку тайлов. Она не заменяет испытания на настоящих сканах препаратов сверхвысокого разрешения. Обычный JPEG в новом просмотрщике декодируется целиком; для больших изображений используйте подготовленные DZI.
