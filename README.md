# HISTOSETS

Настольный интерактивный атлас изображений с описаниями и областями анатомических и гистологических элементов. **update5.2** добавляет постоянный редактор карточек, элементов и векторных областей. Объекты можно создавать, сохранять черновиками, проверять на готовность и повторно открывать. Стартовый экран, просмотр, типовые теги, аналоги и интерфейс RU/EN сохраняются.

## Запуск готовой сборки

1. Откройте [GitHub Actions](https://github.com/PaulChaiko/HISTOSETS/actions/workflows/windows.yml) и успешный запуск проверки нужной ветки или PR `update5.2`.
2. Скачайте артефакт **HISTOSETS-update5.2-windows-x64** из этого запуска. Для скачивания требуется вход в GitHub. Если проверки ещё выполняются или завершились ошибкой, готового артефакта может не быть.
3. Распакуйте **весь архив** и запустите `HistOSets.exe`. Среда .NET включена в сборку Windows x64; файлы и папки поставки должны оставаться рядом с программой.

Приложение открывает стартовый экран. Ранее выбранная база открывается снова; если настройки выбора ещё нет, приложение проверяет прежний каталог `%LOCALAPPDATA%/HISTOSETS/Catalog`. **Отсутствующая база автоматически не создаётся, демонстрационные материалы автоматически не импортируются.**

На стартовом экране доступны:

- **«Выбрать базу данных…»** — выбрать существующий `catalog.sqlite`; **«Выбрать папку…»** — папку, в которой он находится.
- **«Создать пустую базу данных…»** — выбрать пустую папку и задать название. Такая база содержит справочники типов тегов, но не содержит изображений объектов.
- **«Создать учебную демонстрационную базу…»** — при отсутствии выбранной базы явно импортировать комплектные `ATLAS` и `SPECIMENS` в указанную пустую папку.
- **«Просмотр»** — открыть выбранную базу. При пустой базе отображается соответствующее сообщение.
- **«Редактирование»** — открыть список всех объектов, включая черновики без изображения или перевода; создать, изменить или удалить объект.
- **«Управление базой и резервные копии…»** — переименовать базу, создать или восстановить архив, открыть другой каталог либо импортировать XML.

Редактор доступен и для пустой выбранной базы. Самопроверка остаётся последующим обновлением. Замена папки с программой не заменяет отдельно хранящуюся базу.

## Что входит в update5.2

| Возможность | Поведение |
|---|---|
| Каталог | Название, количество объектов и дата последнего изменения на стартовом экране; последний путь запоминается |
| Язык | Интерфейс и содержимое переключаются RU/EN; предпочтение сохраняется между окнами и запусками |
| Основной просмотр | Колесо мыши и `+`/`−` меняют масштаб; перетаскивание перемещает изображение; `100 %` и «Вписать» — разные команды; обзорная миниатюра показывает положение видимой части |
| Области | Показ областей выбранного элемента, включение/выключение, непрозрачность и оттенок; просмотр не меняет геометрию |
| Описания | Краткие тексты в главном окне; полные — в отдельных окнах с регулировкой размера шрифта |
| Поиск | Названия объектов и групп аналогов на обоих языках, без учёта регистра и е/ё; сортировка и сочетание с тегами |
| Типовые теги | Системные типы: автор, организация, предметная область, тема, назначение, прочее; переиспользуемые значения и назначения объектам |
| Аналоги | Самостоятельные группы с названиями RU/EN; объект может состоять максимум в одной группе; название в списке включает группу и название объекта |
| Редактор | Список с миниатюрами, поиском, статусами и типовыми тегами; RU/EN-тексты объекта и элементов; одно основное и дополнительные изображения; назначения тегов и группы аналогов |
| Геометрия | Прямоугольник, эллипс и полигон; перемещение и правка узлов; масштабирование; Undo/Redo рабочей копии; явное сохранение |
| Готовность | Неполные данные сохраняются черновиком; «Проверить и сохранить готовым» проверяет обязательные переводы, основное изображение и используемые справочники |
| Совместимость | Схемы SQLite 1 и 2 обновляются до 3 после полной резервной копии; старые контуры переходят в версионированный JSON отдельных областей |

[Подробная инструкция и приёмка update5.2](docs/update5.2.md). [Структура базы](docs/data-model.md). [План следующих обновлений](docs/ROADMAP.md).

Для начала работы выберите базу → **«Редактирование» → «Новый объект»**, добавьте изображение, заполните тексты и создайте элемент. После выбора элемента доступны инструменты областей. **«Сохранить черновик»** записывает рабочую копию; новая карточка до первого сохранения в базе не появляется.

В этой версии нет кисти, ластика, интерфейса калибровки, измерений площадей/периметров и заданий самопроверки. Кисть, ластик и измерения запланированы в update5.3. Схема 3 содержит 18 таблиц; геометрия хранится в `regions.geometry_json` с версией формата 1, таблица `region_points` заменена при миграции.

## Данные и обновление существующей базы

При первом открытии каталога схемы 1 или 2 создаётся полный архив исходного состояния:

```text
<папка каталога>/BACKUPS/before-schema3-<UTC>-<UUID>.histosets
```

После успешного создания архива выполняется транзакционная миграция до схемы 3. Если обязательная резервная копия или миграция не удалась, приложение сообщает об ошибке. Прежняя выбранная база сохраняется при неудачной попытке открыть другую.

Обновлённую базу следует открывать сборкой update5.2 или более новой совместимой версией. Для возврата к прежней сборке восстановите совместимый с ней архив **до миграции** в отдельную пустую папку. Не заменяйте только SQLite-файл без связанных изображений.

Демонстрационный набор содержит **5 объектов, 5 изображений, 10 переводов карточек, 27 элементов и 33 общие области**. Переключение языков даёт 54 подписи элементов и 66 отображений областей. Пустые описания не заполняются автоматически, одинаковые названия не служат основанием для автоматического создания групп аналогов.

Исходные изображения сохраняются управляемыми файлами с контрольными суммами SHA-256; абсолютные пути автора в базе не используются. Архив `.histosets` содержит базу, связанные изображения и исходный XML, если он импортирован. Один каталог может быть открыт для записи только одним экземпляром приложения.

## Сборка из исходников

Для настольного приложения нужны **Windows, .NET SDK 10 и Node.js 24**. `global.json` задаёт минимальный SDK `10.0.100` с переходом к установленному актуальному feature band ветки 10; версии JS-пакетов зафиксированы в `Viewer/package-lock.json`.

```powershell
npm ci --prefix Viewer
npm run build --prefix Viewer
dotnet build HistOSets.sln -c Release --warnaserror
dotnet run --project HistOSets.csproj -c Release
```

Переносимая сборка:

```powershell
dotnet publish HistOSets.csproj -c Release -r win-x64 --self-contained true -o artifacts/HISTOSETS-update5.2-windows-x64
```

Основной просмотр реализован в WPF и работает без WebView2. Браузерный прототип остаётся в исходниках и технических проверках; его окно требует [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/#download-section). Пробное рисование в прототипе не сохраняет изменения в каталог.

## Проверки

Проверки ядра и хранения запускаются на Windows и Linux:

```powershell
dotnet run --project tests/HistOSets.Core.Tests -c Release -- .
dotnet run --project tests/HistOSets.Storage.Tests -c Release -- .
```

Проверки браузерного просмотрщика используют Python 3.12, Pillow и Chromium для Playwright:

```powershell
python -m pip install Pillow==12.1.1
python Viewer/tests/make-fixtures.py
npm exec --prefix Viewer -- playwright install chromium
npm test --prefix Viewer
```

На Windows дополнительно запускаются проверки настоящих окон, загрузки изображений, редактирования и повторного открытия объектов, сохранения контуров и переходов между стартовым экраном, просмотром и редактором:

```powershell
dotnet run --project tests/HistOSets.Windows.Smoke -c Release -- artifacts
```

Для изоляции пользовательских настроек при проверке можно задать `HISTOSETS_SETTINGS_DIRECTORY` отдельной временной папкой. Это не переносит сам каталог: его путь выбирается отдельно.

Статус проверки конкретного коммита определяется результатами [GitHub Actions](https://github.com/PaulChaiko/HISTOSETS/actions/workflows/windows.yml). Наличие команд в инструкции само по себе не означает успешный CI. Синтетические тайловые изображения проверяют прототип; испытания на реальных сверхбольших сканах отложены после 1.0.

## Служебные файлы и предыдущие этапы

- Настройки пути и языка: `%LOCALAPPDATA%/HISTOSETS/catalog-path.txt` и `language.txt`.
- Журналы ошибок: `%LOCALAPPDATA%/HISTOSETS/Logs`.
- Данные браузерного прототипа: `%LOCALAPPDATA%/HISTOSETS/WebView2`.
- Каталог: выбранная пользователем папка с `catalog.sqlite` и связанными файлами; прежнее расположение — `%LOCALAPPDATA%/HISTOSETS/Catalog`.

[update1](docs/update1.md), [update2](docs/update2.md), [update4](docs/update4.md) и [update5.1](docs/update5.1.md) описывают соответствующие исторические версии. Для текущего запуска используйте инструкцию update5.2.

Исходная версия зафиксирована коммитом [`3722be1`](https://github.com/PaulChaiko/HISTOSETS/commit/3722be1b2a62c445070271d68d45e33be64950f3). Сохраняются логотипы `LOGO/GBL.png`, `LOGO/LOGO2.png` и сиренево-розовая палитра. Уведомления о лицензиях поставляются в `THIRD-PARTY-NOTICES.txt`, `licenses` и файле просмотрщика `Viewer/THIRD-PARTY-NOTICES.txt` готовой сборки. Условия Microsoft WebView2 поставляются с компонентом; [документация по распространению](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).
